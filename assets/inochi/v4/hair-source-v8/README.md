# 胸前两束主要长发源工程

当前模型：GPT-6 Sol。

本阶段处理原画中垂在胸前、压住衣领与胸前蝴蝶结的两束主要长发。主体来自原画 RGB；补画只用于其下的开衫、衬衫、领口及蓝布。没有用生成图替换原立绘中的头发。绕过手臂、一直垂到坐垫旁的外侧长发与后发尚未完成；细卷发、接根及整体轮廓仍需随完整头发终检。

## 重建与工程

```sh
python3 scripts/prepare-v4-chest-locks.py
python3 scripts/separate-v4-chest-locks.py
```

依赖 Pillow、NumPy、opencv-python-headless。`validation.json` 保存偏移、检查参数与范围。

`MewNook-v4-chest-hair-source.ora` 默认原图参考可见；隐藏 `JOINT CHECK — outer side and back hair incomplete` 工作组继承上一版全部部件，并加入两束长发及局部衣服底稿。检查工作组时关闭原图参考。导出经 ZIP CRC、默认参考可见像素及序列化工作组中立状态合成验证，再原子替换。

## 拆层与补画

- 沿原画描出主体范围，胸前蓝布上的小卷发另补全选区。蓝布面对的发丝边缘使用原画邻近深蓝与浅色头发计算透明度；主体保留原颜色，原画深紫色轮廓也保留。
- 左/右主体分别有 13339 / 10756 个核心像素 RGB 与原图一致。对窄边缘重新计算透明度，因此这两个数字不是“整个部件逐像素不变”的声明。
- 内置 imagegen 根据原画胸部裁图和两张标色指南，移除两束长发，续画原有奶油色开衫、白衬衫、领口、纽扣、深蓝蝴蝶结与尾带。要求保持原裁图构图、已露出的衣服和未标记细发，仅消费选区与小范围位移余量。
- 第一版 `inputs/rejected-cutout-costume.png` 把胸部变成带透明边缘的独立对象，根部和发梢缺底稿，未采用。重新生成 `inputs/costume-hidden-generated.png` 时明确要求满幅不透明、四边保持原裁图，不得椭圆裁切或新增背景。代码验证整幅透明度大于 250。
- `registered-costume-hidden.png` 用未编辑区域配准，有 144 个内点 / 371 对匹配，中位误差约 0.368 原图像素，P95 约 0.634。整张生成图只作为隐藏素材输入，不直接替换工作组中的可见衣服。
- 初次检查发现点状蓝边与不完整的细卷发选区；已补全蓝布上的小卷发、剔除孤立碎片，并按原蓝布背景重新计算窄发丝透明度。原蓝布恢复范围只取真实内部，避免把原白发与蓝布混合的边缘留在底稿里形成旧轮廓。

## 检查范围

左右各五档（-6/-3/0/+3/+6）共 25 种组合，根部固定，向发梢递增位移。检查未被当前发丝遮住的原蓝布核心 RGB、胸部修改范围外的上一版工作像素保持不变；两束头发未检测到实心深蓝布污染。深紫色原画发丝轮廓不按蓝布处理。

`chest-lock-joint-motion.png` 显示九个代表组合，`chest-lock-matte-check.png` 为深浅背景部件检查。它们是静态源图位移，不是网格、物理或真实动作验收。本次没有重跑此前全部头部动作组合。

剩余：其余细卷发与胸前边缘终检、外侧长发与后发、肩臂遮挡补画、完整耳根连接；之后还有眼口、正坐姿和实际绑定。第 2 项继续进行，未接入 `/inochi2d-test/smoke`。
