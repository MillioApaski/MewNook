# MewNook · Inochi2D runtime experiment

## Scope and non-goals

This is an opt-in **genuine Inochi2D** WebGL2/WASM experiment with a third-party
rigged sample model. It does NOT generate a Cubism file, does NOT represent a
finished custom MewNook character, and does NOT replace default PNG artwork.

## Run

```bash
npm install
npm run prepare:inochi
npm run dev
```

Open Settings > Virtual Room > Inochi2D Test Mode.
The download is ~18 MB for the rig and ~1 MB for the runtime, but is only
requested by the client when the user enables testing.
WebGL2 is required. The original PNG layer remains visible until the model
successfully loads and is restored on failure.

Only runtime behavior is verified by the default CI build; final WebGL visual
quality needs a real-browser screenshot/regression test.

## Original minimal MewNook rig (new)

`public/inochi2d-test/models/MewNook-test.inx` is now generated by
`scripts/build-mewnook-inx.py` from the MewNook project's existing
`public/assets/rooms/day/character.webp` illustration (not from Aka).

The generator writes a real INP1-compatible `.inx` binary:
`TRNSRTS\0` magic, serialized puppet JSON, and PNG texture blobs.
It contains 8 distinct textured Part meshes and 8 adjustable parameters
(two blinks, two ear rotations, tail sway, breathing, head look and mouth).
The resting image is based on disjoint masks. This is a rudimentary rig;
automatic polygons can leave hard boundaries during large deformations.
There are no professionally animated clips yet.

The new full-portrait artwork made in October 2026 has separately been
prepared as a 14-layer editable OpenRaster file, but it is not yet the
source of this generated test model. Reconcile the two art sources when
moving to a refined hand-rigged version.

Chromium WebGL2 CI now loads `MewNook-test.inx`, not Aka. The
third-party Aka model remains bundled solely for historical/compatibility
testing and keeps its CC BY attribution. The test model is generated
from preexisting artwork inside this MewNook repository.

## 2026-10-15 Inochi2D v2 rig

Generated artifact `public/inochi2d-test/models/MewNook-v2.inx` is
built reproducibly from the repository's owned day scene source using
`scripts/build-mewnook-v2.py`.

- Separate feathered elliptical open-eye textures.
- Inpainted skin behind eye sprites, separately drawn closed lash curves.
- Face/alpha edge cleanup and lower-amplitude independent ear and tail motion.
- 14 parameters including focus and sleep expression inputs, speech mouth,
  smile, blush, and subtle body/head offset.
- Interactive smoke controls for blink, touch, speech and drowsy state.
- A scripted test validates INX structure plus the existing Chromium WebGL2
  loader smoke test.

**Known limitation:** This source is still a flattened illustration; the
eye background repair, tongue and hidden surfaces are estimated and have
not been manually repainted. v2 is an engineering rig, not a finished
Inochi Creator artist-authored deformation rig.

## 2026-10-15: v3 mesh render root causes and fixes

Resolved using real Playwright Chromium WebGL screenshots, not headless
virtual-time WebGL readback alone:

1. Inox2D sorts drawables descending by `zsort`, and then draws them in
   that order. Earlier autogenerated eyes and hair used positive layer
   indices, which placed them behind the base character's skin, producing
   invisible eyes and misleading "zero changed pixels" diagnostics.
2. Inox2D uses `GL_ONE, GL_ONE_MINUS_SRC_ALPHA` for Normal blending.
   The PNG encoder output straight-alpha RGBA with white RGB surviving in
   transparent texels; that caused opaque rectangular ghost overlays.
   The v2 generator now premultiplies every texture, and v3 applies the
   strand mask to **both RGB and alpha**, maintaining the contract.
3. The v3 hair source was destructively inpainted in broad regions, blurring
   faces and hair. The base texture is now left intact, while gently
   feathered mesh overlays provide small deformations.
4. Grid subdivision of eyes disabled the verified blink; eyes retain the
   tested v2 geometry, while hair and tail receive true multi-vertex grids.

The v3 generator's native `deform` tracks now have **no**
`transform.t.x` fallback bindings. Real desktop Chromium screenshot
tests found nonzero pixel changes in left and right hair, front hair, and
tail using deform keys exclusively. The React integration test additionally
loads the model in the full day room.

Known remaining work: paint truly layered replacement art from the newer
character portrait; refine vertex topology, masks, and hidden surfaces in
Inochi Creator; author full focus/typing/rest motion clips.
